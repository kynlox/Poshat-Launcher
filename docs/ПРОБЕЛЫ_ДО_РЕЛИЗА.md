# Пробелы до релиза — Poshat Launcher

Чего не хватает до уверенного публичного релиза.

---

## Критично перед публичным релизом

- Прогнать полноценную релизную сборку: `npm run tauri build`.
- Вручную проверить основные сценарии на чистой системе:
  - первый запуск;
  - создание, редактирование, удаление и дублирование сборки;
  - установка vanilla/Fabric/Forge/Quilt/NeoForge;
  - запуск Minecraft;
  - вход в аккаунт Ely.by и офлайн-аккаунт;
  - установка, обновление и удаление модов;
  - автообновление лаунчера;
  - маленькие экраны и минимальный размер окна.
- Проверить установщик Windows от начала до конца: установка, обновление поверх старой версии, удаление, повторная установка.
- Подготовить канал распространения без Google Drive. `script.iss` сейчас скачивает MSI с Google Drive, для рынка лучше GitHub Releases, Cloudflare Pages/R2 или другой стабильный источник.
- Настроить хеши и подписи релизных артефактов. Для Tauri updater уже указан публичный ключ, но нужно убедиться, что каждый релиз подписывается и `latest.json` обновляется корректно.
- Проверить, что endpoint `https://poshatlauncher.pages.dev/updates/latest.json` реально доступен и содержит актуальные ссылки на релизные файлы.

## Доверие и упаковка проекта

- Переписать `README.md`: сейчас это шаблон Tauri + React + TypeScript, а не описание Poshat Launcher.
- Добавить нормальное описание проекта:
  - что это за лаунчер;
  - чем он отличается от Prism Launcher, Modrinth App и официального лаунчера;
  - какие загрузчики и версии Minecraft поддерживаются;
  - где хранятся данные пользователя;
  - как работает авторизация;
  - как удалить программу и пользовательские данные.
- Обновить метаданные:
  - `package.json`: название пакета лучше сделать npm-совместимым, например `poshat-launcher`;
  - `src-tauri/Cargo.toml`: заменить `description = "A Tauri App"` и `authors = ["you"]`;
  - синхронизировать версии в `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` и `script.iss`.
- Добавить `LICENSE` или явно написать, что проект закрытый. Для доверия open-source лаунчеру лицензия очень важна.
- Добавить страницу/раздел с контактами: GitHub Issues, Discord, Telegram или почта поддержки.
- Добавить понятную страницу донатов: Boosty, DonationAlerts, GitHub Sponsors или другой выбранный канал.

## Безопасность и приватность

- Описать политику приватности: какие данные хранятся локально, какие запросы уходят к Mojang/Modrinth/Ely.by/сайту обновлений.
- Проверить хранение токенов аккаунтов. Сейчас токены есть в локальном store; перед релизом желательно хранить чувствительные данные через системное хранилище ключей или хотя бы явно описать текущую модель хранения.
- Проверить Tauri capabilities: сейчас доступны `opener`, `updater`, `process`. Нужно убедиться, что в приложении нет лишних разрешений.
- Проверить CSP. Сейчас в `tauri.conf.json` стоит `"csp": null`; для публичного релиза лучше включить ограничительную CSP, если это не ломает нужные сценарии.
- Снизить подозрительность сборки. Сильная JS/Rust-обфускация может выглядеть плохо для open-source-аудитории и антивирусов. Если проект будет открытым, лучше объяснить или отключить лишнюю обфускацию в публичной сборке.
- Прогнать релизные артефакты через VirusTotal/Defender и зафиксировать результат для себя перед публикацией.

## Качество и поддержка

- Добавить минимальный набор автотестов для backend-логики:
  - валидация имён сборок;
  - сохранение/чтение store;
  - пути установки;
  - обработка некорректных данных.
- Добавить smoke-чеклист в репозиторий, чтобы перед каждым релизом проходить одинаковые сценарии.
- Настроить CI для `npm run build` и `cargo check`/`cargo test`.
- Проверить поведение без интернета: каталоги, версии, моды, вход, запуск уже установленной сборки.
- Проверить поведение при битых/частично скачанных файлах.
- Проверить восстановление после отмены установки версии или загрузчика.
- Проверить логи ошибок: пользователю должно быть понятно, что сломалось и что делать дальше.

## Продукт и рынок

- Сформулировать одну сильную причину пользоваться Poshat Launcher. Просто "ещё один Minecraft launcher" будет сложно продвигать.
- Выбрать основную аудиторию:
  - русскоязычные игроки;
  - сборщики модпаков;
  - пользователи Ely.by;
  - люди, которым нужен простой красивый лаунчер без лишней настройки.
- Добавить видимую уникальную фишку:
  - удобный импорт/экспорт сборок;
  - автонастройка Java;
  - простой менеджер модов;
  - красивый UX;
  - понятная русская поддержка;
  - прозрачная приватность.
- Подготовить сайт или GitHub-страницу с:
  - скриншотами;
  - кнопкой загрузки;
  - инструкцией установки;
  - блоком "почему можно доверять";
  - ссылками на исходники/релизы/донаты.
- Подготовить первые релизные скриншоты и короткое видео/gif с основным сценарием.
- Сделать roadmap: что будет в следующих версиях и почему пользователю есть смысл следить за проектом.
