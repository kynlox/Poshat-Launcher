# Архитектура — Poshat Launcher

Внутренние заметки по архитектуре. Не для публики.

---

## Стек

- **Backend**: Rust + Tauri 2
- **Frontend**: React 19 + TypeScript + Tailwind CSS 3
- **Сборка**: Vite 7 + Tauri CLI 2
- **MC Installation**: lyceris (Rust crate)

## Структура проекта

```
src-tauri/src/
  lib.rs          — точка входа, 60+ Tauri commands
  accounts.rs     — аккаунты (офлайн + Ely.by)
  catalog.rs      — Modrinth API (моды/шейдеры/ресурспаки)
  elyby.rs        — Ely.by Yggdrasil авторизация
  http.rs         — HTTP клиент с retry + зеркалами
  instances.rs    — CRUD инстансов, .mrpack, ярлыки
  java.rs         — Java runtime (заморожен, lyceris делает)
  launch.rs       — запуск Minecraft, process management
  loaders.rs      — версии загрузчиков (Fabric/Quilt/Forge/NeoForge)
  mc_install.rs   — установка через lyceris
  paths.rs        — директории (%APPDATA%/.poshatlauncher/)
  security.rs     — anti-debug (IsDebuggerPresent)
  store.rs        — JSON store (совместим с electron-store)
  versions.rs     — Mojang manifest с 2-уровневым кэшированием

src/
  api/poshatAPI.ts     — шим совместимости с Electron API
  app/page.jsx         — главный компонент (781 строка, хаб состояния)
  components/Launcher/ — 26 UI-компонентов
  data/                — статические данные (секции, моды, темы)
  hooks/               — хуки (versions, loaderVersions, installedVersions)
  utils/               — updater, аккаунт-хелперы, анимации
```

## Ключевые решения

### Почему lyceris, а не своя установка
lyceris — готовый Rust crate для установки/запуска Minecraft. Покрывает:
- Скачивание клиента, библиотек, ассетов, нативов
- Установку Java runtime
- Запуск с правильными JVM-аргументами

Свою реализацию держать дорого и багово. lyceris делает это за нас.

### Почему шим-совместимость с Electron
UI был написан за 6 месяцев для Electron. Переписывать 26 компонентов с нуля — нерационально. Шим `poshatAPI.ts` позволяет UI работать с Tauri без изменений.

### Почему parking_lot, а не std::sync::Mutex
parking_lot быстрее и удобнее:
- Нет poisoned state (паника в одном потоке не лочит другие)
- Try-lock поддержка
- Меньше overhead

### Почему obfstr для строк
Компилятор шифрует строки при компиляции. В .exe лежат зашифрованные байты. `strings program.exe | grep ely.by` ничего не покажет. Важно для URLs API.

### Почему атомарные запись (temp → rename)
Если процесс умрёт во время записи .jar, файл останется полу-записанным. Minecraft крашится на битых .jar. Temp + rename решает это.

## Потенциальные проблемы

1. **Нет тестов** — при рефакторинге легко сломать
2. **Токены в JSON** — не зашифрованы, не в keychain
3. **CSP = null** — раздёрнутая безопасность
4. **Обфускация JS** — может вызвать проблемы с антивирусами
5. **Нет CI/CD** — ручная сборка, легко забыть проверить
